| Contract                 | Short description                                                                                                                                                                                                     |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `unit`                   | Waits for exactly one item from each required input, then invokes the module once. Good for setup/config-style modules. Duplicate or missing required inputs are usually errors.                                      |
| `zip`                    | Pairs items from multiple streams by position: first with first, second with second, and so on. Useful only when streams are guaranteed to stay aligned. Length mismatches are usually errors.                        |
| `keyed_join`             | Groups incoming items by a correlation key, such as `test_id`, and invokes the module when all required inputs for that key are present. This was meant to be the main workhorse.                                     |
| `latest`                 | Maintains the latest value from one or more state/config inputs and invokes the module whenever a trigger input arrives, using the current latest state. Useful for “latest config + each work item” patterns.        |
| `broadcast`              | Treats an input as shared context that should be reused across many invocations, rather than matched one-to-one. Usually used as an input mode inside another contract rather than as a complete contract on its own. |
| `required_inputs_by_key` | A more explicit name for `keyed_join`: group by key and wait for listed required ports.                                                                                                                               |
| `group_until_end`        | Accumulates many items for a key until a group or stream end sentinel arrives, then emits one invocation with the collected batch. Useful for logs or reports.                                                        |
| `branch_aware_join`      | Waits for required inputs while accounting for control-flow branches that may intentionally skip some ports. Useful for fan-in after `if/else` routing.                                                               |
